# Mongolz — адаптивный интернет-магазин (KR3 → практики 13–15)

Многостраничный сайт на чистых HTML, CSS и JavaScript (без фреймворков): магазин монгольских изделий ручной работы.
Репозиторий: `kr3-responsive-shop`.

## Страницы

| Файл | Назначение |
| --- | --- |
| `index.html` | Главная: баннер, популярные товары, калькулятор заказа |
| `catalog.html` | Каталог: фильтры, сортировка, поиск |
| `product.html?id=N` | Карточка товара, калькулятор, характеристики, сравнение |
| `about.html` | О нас |
| `contacts.html` | Контакты, карта, как найти офис, вопросы и ответы |
| `favorites.html` | Избранное |
| `login.html`, `account.html` | Вход, регистрация, личный кабинет |

## Практика 13. JavaScript: данные, операторы, функции

Файл `js/utils.js` подключён ко всем страницам через `defer`. Результат виден в консоли браузера (F12 → Console).

- **Типы данных.** Объект товара `sampleProduct` содержит строки (`name`), числа (`price`, `rating`), логические значения (`inStock`, `isNew`) и вложенный объект (`specs`). Типы выводятся через `typeof`.
- **Операторы.** Арифметические — в `calcDiscount` (`price * percent / 100`, `price - discount`); сравнения и логические — в `getProductStatus` (`>`, `>=`, `!`, `&&`, `||`).
- **Функции:**
  - `formatPrice(price)` — «18 900 руб.»;
  - `calcDiscount(price, percent)` — размер скидки и итоговая цена;
  - `getProductStatus(product)` — «Нет в наличии», «Выгодное предложение», «Скидка», «Новинка», «Выбор покупателей», «В наличии»;
  - `getShortDescription(product)` — краткое описание одной строкой.
- **Вывод в консоль.** `console.log` для каждой функции и `console.table` по всем 10 товарам из `js/products.js`.

## Практика 14. Проверка адаптивности

Проверено скриптом `docs/audit/responsive-audit.js` (Playwright) на ширинах **320, 375, 768, 1024 и 1440 px** для всех 8 страниц. Отчёт: `docs/audit/responsive-report.txt`.

**Адаптивная вёрстка страниц**
- нет горизонтальной прокрутки ни на одной странице;
- Mobile First: базовые стили для телефона, `@media (min-width: …)` расширяют сетку (1 → 2 → 3–4 колонки карточек, меню-бургер на узких экранах).

**Responsive images**
- фото товаров в двух размерах (`p{id}-480.webp`, `p{id}-960.webp`), у каждого `srcset` + `sizes`, заданы `width` и `height` (нет скачков вёрстки), `loading="lazy"`, `decoding="async"`;
- баннер — SVG, масштабируется без потери качества, внутри `<picture>`.

**Адаптивные формы и таблицы**
- поля форм (заявка, вход, регистрация, фильтры, калькулятор) не выходят за экран на 320 px, высота ≥ 40 px, шрифт ≥ 16 px (нет автоприближения в iOS);
- таблицы (характеристики, сравнение) лежат в контейнере `.table-scroll` с горизонтальной прокруткой, `role="region"`, `aria-label` и `tabindex="0"` (прокрутка с клавиатуры).

**Найдено и исправлено:** на 320 px калькулятор был шире экрана (горизонтальная прокрутка на главной и странице товара) — добавлены `min-width: 0` для колонок и `fieldset` (`css/mongolz.css`).

## Практика 15. Доступность

### Проверка изображений и альтернативных описаний
- у всех содержательных `<img>` есть осмысленный `alt` (название товара, описание баннера); декоративные SVG-иконки скрыты через `aria-hidden="true"`;
- автопроверка: нет `<img>` без `alt`, нет пустых `alt` у значимых картинок, нет «картинка…» в начале `alt`.

### ARIA — только там, где нужно
Используются только атрибуты, которых нет у нативных элементов:
- `aria-pressed` — кнопки «В избранное» (переключатель);
- `aria-expanded` + `aria-controls` — меню-бургер, поиск, чат;
- `role="search"`, `role="combobox"`/`listbox` + `aria-autocomplete` — подсказки поиска;
- `role="dialog"` — окно заявки; `role="log"` — сообщения чата; `role="status"`/`aria-live` — результаты фильтра, промокод, подписка;
- `role="alert"` — ошибки форм; `aria-describedby` — связь поля и подсказки/ошибки;
- `aria-current="page"` — текущая страница в меню; `aria-label` — иконки-кнопки (поиск, тема, избранное, «Вверх») и несколько `<nav>`;
- `role="region"` + `aria-label` — прокручиваемые таблицы.

Лишних ролей нет (нет `role="button"` на `<button>`, `role="navigation"` на `<nav>` и т. п.): автопроверка не нашла ссылок `aria-labelledby/describedby/controls` на несуществующие `id`.

### Остальные проверки
- **Семантика:** `lang="ru"`, один `<h1>` на странице, заголовки без пропуска уровней, `<header>`, `<nav>`, `<main>`, `<footer>`, ссылка «Перейти к содержимому».
- **Навигация и фокус с клавиатуры:** пройдены все элементы Tab на каждой странице (от 26 до 67 остановок) — у каждого виден фокус (`:focus-visible`, у поля поиска — кольцо вокруг всей строки; в `css/mongolz.css` оно усилено до 3 px).
- **Контрастность:** проверены все текстовые узлы в светлой и тёмной теме (обычный текст ≥ 4.5:1, крупный ≥ 3:1) — замечаний нет.
- **Подписи полей форм:** у каждого поля есть `<label>` или `aria-label`.
- **Кнопки, ссылки и интерактивные элементы:** у всех есть доступное имя; нет ссылок «здесь» и «читать далее».

### Автоматическая проверка (`docs/audit/`)
`node docs/audit/a11y-audit.js` (нужен Playwright) проверяет 8 страниц в светлой и тёмной теме: `lang`, заголовки, landmark-элементы, `alt`, имена кнопок и ссылок, подписи полей, `id`, ARIA, таблицы, контраст.

Результат (`docs/audit/a11y-report.txt`): **0 замечаний на 16 проверках (8 страниц × 2 темы)**. Скрипт проверен на заведомо неправильной разметке — он находит такие ошибки.

## Калькулятор заказа
`js/calculator.js`: цена × количество + услуги (упаковка, вышивка/гравировка, пошив по меркам, страховка) − скидки (5% от 3 шт., промокоды `NAADAM10`, `MONGOLZ5`) + доставка; итог в валюте выбранной страны.

## Запуск
Открыть `index.html` в браузере (сервер не нужен). Данные пользователей, избранное и тема хранятся в `localStorage`.
